Scope: full re-run of the test suite plus four parallel static reviews of the
uncommitted modernization work (JIT core / runtime, optimizer passes, autograd +
VJP readiness, CPU/CUDA backends + ops). Top claims were then verified with
scratch probes kept outside the repo. Nothing in the repo was
modified by this review.

**Status update (later on 2026-10-26):** most §1-§2 bugs that did not need a
design decision were fixed in the working copy — see TODO.md "Fixes applied
2026-10-26". Still open: §1.1 (optimizer / Tensor alias semantics), VJP
graph-retention model, compaction policy, ArrayFire default, plus the

- **[REPRO]** reproduced at runtime on this machine (8x H100, conda env

## 1. Verified critical issues (fix first)

1. **Optimizers never update module parameters — training is a no-op.** [REPRO]
   Probe: `Linear(4,3)` + `SGDOptimizer(model.params(), 0.1)`; loss of
   `sum(model(x))` is bit-identical after 3 steps on CPU and CUDA.
   Mechanism [READ]: `Tensor(const Tensor&)` calls `impl_->clone()` → new
   `JitTensorBase::SharedData` (`Tensor.cpp:42-44`, `JitTensorBase.cpp:331`).
   Copies share `AutogradMeta` but not data. `Module::params()` /
   `Container::add` hand out copies; optimizers store copies
   (`optim/Optimizers.cpp:14-15`); `data = data - lr*grad`
   (`SGDOptimizer.cpp:65`, same in all 8 optimizers) rebinds only the
   optimizer's copy, records autograd (`autogradSub`), and move-assign replaces
   the meta (`Tensor.cpp:280-284`) → from step 2 `isGradAvailable()` is false
   and the step is skipped; `opt.zeroGrad()` clears the wrong metas so model
   grads accumulate as a never-evaluated `grad + childGrad` chain that pins
   every step's fwd/bwd graph (eventual OOM). `OptimTest.SerializationTest`
   passes only because neither param set is ever updated.
   Root cause is an API-semantics gap from the Variable→Tensor merge: Variable
   shared data **and** grad; Tensor copies share only grad. Needs an explicit
   decision on value vs alias semantics (see §4.1).

2. **CPU async-stream lifetime race → heap corruption.** [REPRO]
   `AutogradConv2DTest_CPU.WeightNormConv` and `CPUTensorTest` abort with glibc
   malloc corruption ("corrupted double-linked list", "malloc_consolidate():
   unaligned fastbin chunk"). Probabilistic: crashes in ~2/3 runs at
   OMP_NUM_THREADS ∈ {128,256,384}; not observed at 16/64 (tiny OneDNN ops run
   ~20x faster there, shrinking the window). Passes 5/5 with an `LD_PRELOAD`
   shim that makes `AsyncCPUStream::enqueue` run tasks inline, and passes under
   ASAN's allocator (quarantine hides use-after-free writes by uninstrumented
   OneDNN code). Not the conda environment (reproduces under an activated env too).
   Candidate causes [READ]: (a) async lambdas keep inputs alive but not the
   pre-assigned `out` buffer (`OneDnnOps.cpp:635-640,722-726`) while
   `Evaluator::executePlan` `unsetResult()`s dead intermediates on the host;
   (b) CPU concatenate's contiguous copies are freed before the queued concat
   reads them (`OneDnnOps.cpp:1184-1232`); (c) `executeNetwork` running
   conv/pool/bn on the host thread. Diagnostic tools built:
   an `LD_PRELOAD` shim that runs `AsyncCPUStream::enqueue` tasks inline, and a
   CPU-only ASAN build (see `docs/modernization/DEVELOPMENT.md`).

3. **AlgebraicSimplification identity rules ignore shape/dtype** → the
   rank≥2 broadcast failure (`TensorBinaryOpsTest.BroadcastRankMismatch`,
   CPU+CUDA). [REPRO] `x+0, 0+x, x-0, x*1, 1*x, x/1, x^1` return the operand
   (`AlgebraicSimplification.cpp:51-101`); `{4} + full({2,3,4},0)` collapses to
   the `{4}` operand (materialized ndim=1). `0-x→neg(x)`, `x^2→x*x`,
   `x^0.5→sqrt(x)` have the same flaw when the scalar side is the larger
   shape; dtype changes too (`b8_mask * 1` should be s32; f16 + f32-zero
   tensor should be f32; `int^0.5 → sqrt(int)`). The test only fails because it
   adds `full(…, 0)`; the kernels' broadcasting is correct. GraphVerifier misses
   it because nothing checks root shape/dtype preservation across a pass.
   Also: this pass deleting identity `reshape(x, x.shape())` is what exposed
   the GLU bug (item 7).

4. **`fl::copy` same-device "Unknown dtype"** (`CopyTest_CUDA`
   FunctionalCopy_SameDevice/StridedSrc; also `CudaTensorIndexTest.*`). [REPRO]
   Three stacked bugs: (a) nodes created without an explicit stream
   (`fl::full`, `fl::rand` → `ScalarNode`/`CustomNode` with null stream) defeat
   `TransferNode::create`'s same-device no-op (`TransferNode.cpp:31-35`);
   (b) `CudaBackend::copy` with empty `dst` treats *every* device src as D2H and
   allocates a pinned-host `CPUTensor`, even for CUDA→CUDA
   (`CudaBackendTransfer.cpp:28-43`); (c) `Tensor::getAdapter<T>()` is an
   unchecked `static_cast` (`Tensor.h:440`), so the next CUDA kernel reads the
   CPUTensor as a CudaTensor and `dtypeSize()` sees a garbage `type_`.

5. **CPU gelu hang** (`AutogradComposedTest_CPU.GeluLinearJacobian`). [READ,
   consistent with REPRO hang + earlier gdb] Root cause is NOT where the old
   TODO pointed. `findAnchorChain` (`OneDnnPrimitivePostOpFusion.cpp:178-200`)
   pushes the activation before the input-use check; when `z` has 2 internal +
   1 external use (autograd `AutogradMeta.inputs`), it breaks without advancing
   `cur`, so `cur` is the gelu root; the standalone-gelu branch (:309-315)
   builds a CustomNode whose input is the node it replaces → `replaceAllUsesWith`
   creates a self-cycle. `OneDnnOpFusion` then spins because non-fusable nodes
   are never marked visited (`OneDnnOpFusion.cpp:186-190`) — on acyclic graphs
   that "only" causes exponential path re-expansion. Same bug silently computes
   `gelu(-(-x))` for `gelu(neg(x))` with shared `x`. Fix: `pop_back()` before
   `break`; guard `anchorNode != node`; per-apply local worklist/visited.

6. **ArrayFire+CUDA initialized in every `_CPU` test; AF default path
   segfaults.** [REPRO] `DefaultTensorType` ctor (thread_local) eagerly calls
   `DefaultTensorBackend_t::getInstance()` = ArrayFire (`TensorAdapter.cpp:30-43`),
   contradicting TODO "lazy init". With AF as the compile-time default,
   `TensorBackend::jitStream()` returns nullptr and `JitBackend::defaultStream()`
   dereferences it (`JitBackend.cpp:100-102`) — this is the cause of the
   unsuffixed `Jit*Test` SIGSEGVs previously dismissed as "AF path, not real".

7. **CPU `ModuleTest.GLUFwd`.** [READ] `gatedlinearunit` slices a {3,2} input
   with `(span, range(1,2))` → strided view {3,1}/strides {2,1}. The old identity
   reshape that forced a contiguous copy is now removed by AlgebraicSimplification;
   `applyEltwiseOp` builds src md with view strides but dst md contiguous, and
   OneDNN eltwise requires src md == dst md (`OneDnnOps.cpp:691-711`). Part of a
   wider class: CPU native ops ignore strides entirely (§2.4).

8. **CUDA mixed-dtype result drift** (`CudaTensorBinaryOpsTest.MixedBf16F16Compute`).
   [REPRO] bf16+f16: IR infers f32, runtime buffer holds bf16 (reads back
   2.3e-41 = 0x00004040). [READ] CUDA arithmetic/bitwise return `lhs.type()`
   while IR promotes (`CudaBinaryOps.cu:236,273-309`); `where` reads f32 as
   `double*` for mixed dtypes (`CudaUnaryOps.cu:539-594`); s32 matmul → f32.

## 2. High-severity issues found by reading (not yet reproduced)

### 2.1 Evaluator / runtime / JIT core
- **Up-front allocation of every intermediate.** [READ, verified by me]
  `Evaluator::eval` = buildPlan → `assignBuffers` (allocates `ctx->empty()` for
  every non-view node) → executePlan (`Evaluator.cpp:793-824`). Peak memory =
  sum of all intermediates, defeating use-count freeing. Single-output
  `CustomNode` and `IndexedUpdate` never `takeOutputBuffer` (`:100-122`,
  `:192-232`) → every lowered (NVRTC/OneDNN/cuDNN/cuBLASLt/backward) node holds
  two output-sized buffers for its lifetime. Likely contributor to CUDA OOMs.
- **Passes rewrite already-evaluated nodes.** No pass treats `getResult()` as a
  leaf (`Pass.cpp:15-85`, `ElementwiseFusion.cpp:26`): evaluated history is
  re-optimized every eval (O(history) host cost, 9-10 GraphVerifier walks per
  eval) and absorbing an evaluated node discards its result → recompute,
  including lazy `rand` recomputed with *new values*.
- **AsyncCPUStream worker dies on first exception** (`AsyncCPUStream.cpp:119-128`):
  first `sync()` rethrows, then every later `sync()` hangs forever on the
  process-wide CPU stream. Trigger: any worker-side throw (e.g. bf16 sort/cumsum
  via `dispatchByType`). TODO §Error Handling promises a sticky error state.
  Destructor self-detach path is a use-after-free; `Device::addStream` leaks
  threads.
- **Node stream ≠ execution stream.** `BackendDispatch` has no stream arg; CPU
  runs on `lhs.stream()`, CUDA always on the backend singleton, but CUDA
  `empty()` honors the node stream → buffers alloc/free on s2 while kernels run
  on the singleton; sync edges only when *both* streams are explicit.
- **Futures**: `isReady()` can stay false forever (CUDA→host event lives on a
  hidden transfer tensor; already-evaluated nodes skip event recording);
  `get()` runs `fl::eval` + full `stream().sync()` contrary to its docs; data
  race on `value`; same-device futures capture the tensor by reference (a later
  `t += 1` changes the future's value on CPU but not CUDA). TODO lines 908-918 /
  955 describe an API that doesn't exist (shared_future, wait_for, Future.cpp).
- **Lazy `device()` on a view attaches a view-sized buffer to the base node**
  → OneDNN writes base-sized output into it (heap overflow)
  (`JitTensorBase.cpp:199,417-418`); `outputBuffer_->copy()` is a deep copy.
- **CPU `Tensor` copy = blocking sync + deep memcpy** (`CPUTensor.cpp:285-327`)
  while CUDA copy is shallow — inconsistent adapter contract, and hidden in eval
  paths (Projection eval, Concatenate inputs, FusedElementwise inputs,
  shared-cache returns). Every CPU elementwise chain hits this because
  ElementwiseFusion preempts OneDnnOpFusion and the evaluator runs
  FusedElementwise op-by-op.
- **Cross-device tensors bound to the source JitBackend**; the backend-equality
  check compares `Jit == Jit` so mixed CPU/CUDA graphs fail deep inside eval.
- Backward CustomNodes re-run forward via nested `eval` (check `getResult()`
  instead of cached state; cuDNN BN always returns null state).
- 6 shared-cache multi-output sites pin memory and bypass dead-output
  elimination (`JitBackend.cpp:404-676`, `JitBackendAutogradOps.cpp`).
- `JitTensorBase::stream()` BFS without visited set (exponential on DAGs);
  recursive node teardown (stack overflow on 10^4-10^5 chains); dangling
  reference after `stack.pop()` in `buildPlan` (UB that works by accident);
  `replaceAllUsesWith` has no cycle guard.
- Multi-tensor `fl::eval(tensors...)` (TODO: done) does not exist — only
  `eval(Tensor&)`; prerequisite for deferred fwd+bwd.

### 2.2 Optimizer passes
- **TransposeSimplification** folds `reduce(transpose(x,p),axes)` without
  checking the surviving axes keep order → silently transposed results
  (`TransposeSimplification.cpp:164-188`).
- **cuBLASLt backward epilogues**: BGRADB reduces the wrong operand (length M,
  not N) and overruns its `{1,N}` buffer when M > N; DGELU matcher accepts
  forward gelu (`matmul(a) * gelu(b)` → `gelu'(b)`, breaks GEGLU) and passes
  unpadded aux ld (must be %8); cuBLASLt path ignores batch dims/rank (only
  first batch computed). Recommendation: delete BGRADB, restrict to 2-D.
- **cuDNN subgraph lowering**: in-subgraph TransposeNodes silently dropped
  (`CudnnSubgraphLowering.cpp:521-530`); transpose views recorded per node not
  per use (`matmul(x,x,N,T)` computes xᵀxᵀ); training-BN multi-output root
  returns the multi-output node (bad tensor binding); trailing-1 `shapeTo4D`
  misaligns numpy broadcasts; graphs rebuilt + plans compiled **every eval**
  (`CudnnPlanCache` has zero users); greedy O(chain) retries, O(n²) expansion.
- **cuBLASLt DRELU Jacobian failures are not a tolerance issue**: the
  single-layer `ReluLinearJacobianWeight` graph contains no `mul(mask, matmul)`
  at all; suspects are the cuDNN transpose drop and TF32 engines. Bisect: run
  with CudnnSubgraphLowering disabled / CublasLt pass disabled /
  `NVIDIA_TF32_OVERRIDE=0`.
- OneDnnPrimitivePostOpFusion f64 fallback drops bias/residual adds.
- ScalarFolding: comparisons fold to operand dtype instead of b8; integer `x/0`
  evaluated in the optimizer (SIGFPE).
- CSE keys scalars with 6 significant digits → merges distinct constants.
- OneDnnOpFusion output dtype = widest input (wrong for comparison chains).
- NVRTC fusion computes everything in f32 (ints > 2^24, int division, bit ops)
  and uses `--use_fast_math`.
- ConvBatchNormFolding mixes `fl::full` (JIT) with bare tensors.
- **GraphVerifier**: no dtype checks, no root shape/dtype preservation, no
  cycle detection, orphaned-ExternalUse check can never fire, one-directional
  use-list check; always-on after every pass in release builds.
- Pass ordering: on CPU ElementwiseFusion runs before OneDnnOpFusion so CPU
  gets no elementwise fusion benefit; on CUDA cuDNN claims patterns before
  cuBLASLt (GPU/cuDNN-version dependent); nothing runs to fixed point.
- Dead/duplicated: FusionUtils.h (dead), PatternMatcher.h (586 lines, 1 trivial
  user), 8 copies of single-use helpers with two meanings, 16 TODO mentions of
  deleted CudaMatmulEpilogueFusion/CudnnConvEpilogueFusion.

### 2.3 Autograd
- **F1 optimizer** (see §1.1).
- **`withoutData()` allocates a full-size uninitialized device buffer** per
  recorded input, even in inference (`TensorAutograd.cpp:144` →
  `getDefaultAdapter` → `cudaMallocAsync`); e.g. `Linear::forward`'s
  `params_[0].astype(...)` allocates a weight-sized dead buffer every call.
- **`Tensor& detach() const` returns a reference into
  `AutogradMeta::detachedViews`**: `x.detach() = y` is a no-op for grad tensors
  but rebinds non-grad tensors; unbounded growth until `zeroGrad()`, which then
  dangles held references. Breaks `examples/LinearRegression.cpp`,
  `pkg/speech` CriterionTest:302/371, AutogradUnaryOpsTest Clip nudging.
- BatchNorm `runningMean_/Var_` rebound to never-evaluated projections →
  BN_k→Proj→BN_{k-1} chain retains every step's outputs [SUSPECT, strong].
- backward clears `inputs` but keeps `gradFunc` (residuals + Deferred*State
  pinned; second backward indexes an empty vector — UB); a non-leaf receiving
  no gradient throws (weightedCCE); in-place / indexed writes on grad tensors
  silently produce wrong gradients (no version counter); shared meta makes
  `setRequiresGrad(false)` / hooks affect all copies; optimizer math records
  autograd (SGD velocity meta chain); `tile` backward wrong for non-singleton
  tiles; `maximum/minimum(T,T)` backward lacks `sumAs`; `flatten()` /
  `asContiguousTensor()` drop autograd.
- Forced syncs/barriers inside autograd: softmax/logSoftmax/norm call
  `fl::eval` in forward; CCE `scalarSync`; tensor-index backward does
  per-element `scalarSync`; embedding backward = host `indexAdd` round trip.

### 2.4 Backends / ops
- CPU concatenate use-after-free of contiguous copies (§1.2 candidate).
- CUDA flip/roll use the `<float>` kernel for every non-f64 dtype → 2-4x
  buffer overrun for f16/bf16/b8/u8/s16 (`CudaUnaryOps.cu:417-462`).
- **CPU native ops ignore strides** (sin/cos/floor/ceil/log1p/erf/isnan/int abs,
  pad/flip/roll/tril/triu, sort/argsort/topk, cumsum, min/max/argmin/argmax):
  lambdas rebuild inputs with contiguous strides → silently wrong on views.
  CPU `where` with strided x scrambles output.
- Out-of-bounds indexing: literal index == dim accepted (`>` vs `>=`),
  unchecked tensor-index gather, range stride 0 divide-by-zero; CUDA tensor
  index at position > 0 gathers dim 0.
- CPU BatchNorm training throws for momentum ≠ 0 (nn default 0.1); returned
  saveMean/newRunningMean are stale pre-execution copies.
- Backend ops returning JIT tensors from inside eval (empty `nonzero`, CPU
  `var`) — violates the "bare tensors inside eval" rule.
- CPU bf16: sin/cos/floor/ceil/log1p/erf return uninitialized memory;
  `dispatchByType` lacks bf16/f16/s64/u64/u16 (throws on the worker → §2.1 hang).
- Integer semantics: u32→s32, s16/u16→f16, s64/u64→f64 storage mappings get
  reinterpreted by `reorderAstype`; OneDNN computes s32 binary ops in f32
  (round-to-nearest division vs CUDA truncation); CUDA computes all integer
  math in f32.
- CPU OneDNN path rejects rank > 4; empty-tensor divide-by-zero in native
  cumsum/sort; `getSizeInBytes` returns `unsigned` (>4 GiB truncation);
  32-bit index math on CUDA.
- Perf: `relativeSync` calls `backend().eval()` → full `stream().sync()` on
  every CPU binary/matmul/where/concat (host blocks per op; no CPU async
  overlap at all); CPU reshape always copies; host round-trips (`indexAdd`,
  `executeNetwork`, pow/mod/bitwise/logical loops); Thrust `par.on` syncs;
  cuDNN frontend graphs uncached; `Tensor out;` placeholders allocate a
  CPUTensor + JitTensorBase + ValueNode per op.

## 4. Cross-cutting themes and recommended guardrails

1. **Value vs alias semantics of `Tensor` must be decided explicitly.**
   Today: CPU copy = deep (blocking), CUDA copy = shallow, JIT copy = new
   SharedData over the same node, autograd meta shared on copy. The optimizer
   bug, the detach() bug and the shared-meta surprises all come from this.
   Recommendation: value semantics for data (SSA; copies are cheap because they
   share the immutable node), explicit `alias()`/in-place assignment for
   parameter identity (modules + optimizers), autograd meta NOT shared by plain
   copies (or shared only through an explicit parameter handle).
2. **IR metadata vs runtime drift** (broadcast, copy, bf16+f16, CUDA int math,
   ScalarFolding compare dtype, OneDnnOpFusion dtype, MultiValueNode slot-0
   shape). Guardrails: (a) debug-mode evaluator check after every node:
   result shape/dtype == node metadata and backend == expected; (b)
   GraphVerifier: root shape/dtype preservation per pass, cycle detection,
   dtype rules; (c) `getAdapter<T>()` asserts the adapter's backend type in
   debug builds.
3. **Async CPU lifetime discipline.** Every enqueued lambda must own (by value)
   every buffer it touches, including `out`. Add an env/debug switch to make
   AsyncCPUStream synchronous, and ASAN + TSAN build configs. Make the worker
   survive exceptions (sticky error).
4. **Evaluated history is a leaf.** Passes, verifier, buildPlan, stream
   inference must all stop at nodes with results. Decide a compaction policy for
   every external holder (not just the evaluated root).
5. **Memory**: allocate at dispatch time (or plan with liveness), consume or
   skip pre-assigned buffers, remove shared-cache sites, fix `withoutData`,
   BN running stats.
6. **Stale docs/memory**: TODO claims that are false today — lazy backend init,
   Future API, multi-tensor `fl::eval`, "nothing in Functions.cpp forces eval",
   "FusionSideOutput obsolete with VJP", "unsuffixed Jit crashes are not real",
   references to deleted cuBLASLt/cuDNN conv epilogue passes, `getTensorOrEvalNode`.
7. **Modifiability (paper's core metric)**: ~14 files to add an IR node type,
   ~22 to add a backend op; BackendDispatch has 50-57 pointers in two
   hand-written tables (design said ~10). Ideas: X-macro node list; small
   virtuals on Node (`evalInto`, `appendCseKey`, `printParams`,
   `consumesOutputBuffer`) to delete the evaluator/CSE/printer switches; keep
   either TensorBackend virtuals or one dispatch table. ~1.2k LOC deletable now
   (makeBackendDispatch trampolines, OneDnnOps forwarding wrappers, unused named
   CPU ops, autograd-op forwarders, dead f64 fallbacks, unused CudnnPlanCache or
   wire it up). ArrayFire: ~5.5k LOC backend + ~2.2k LOC tests, default-on,
   forces generic allocations in cuDNN code; removing it (or making it opt-in)
   also fixes §1.6.

## 5. VJP readiness

### 5.1 Design corrections to the VJP plan (TODO Phase 4 + vjp-design-research.md)
- "The forward JIT graph IS the residual store" holds only if backward is
  built **before** the first eval of the forward. Today `fl::eval` optimizes in
  place (`replaceAllUsesWith` on shared nodes), compacts the root, and frees
  intermediates by use count; typical loops read `loss.scalar()` before
  `backward()`, and autograd forces evals internally (softmax/norm). After that
  a VJP walk sees FusedElementwise / lowered CustomNodes / ValueNodes.
  Options: (i) functional `valueAndGrad(f)` that builds fwd+bwd before eval
  (JAX/MLX model; `loss.backward()` errors or falls back if the fwd was already
  evaluated); (ii) optimize a *copy* (or keep provenance) so the semantic graph
  survives eval while grad-requiring tensors reference it; (iii) keep the tape
  for target identification and only use VJP rules for the math (Phase A below).
- RNG nodes (rand/dropout) must never be recomputed; residual policy needed.
- **FusionSideOutput is not obsolete**: `isSingleUse` counts internal uses, and
  any forward value consumed by a backward rule has ≥ 2 uses, so fusion passes
  won't absorb it. Need side outputs or a recompute policy.
- Gradient-target option (b) "flag on Node" is unsound (`detach()` and
  `Tensor(x,false)` share the node); (a) is ambiguous (clones create multiple
  SharedData per node); (c) explicit parameter list + a `StopGradient` node + a
  registry for argument-less `backward()` is workable.
- New nodes needed: StopGradient, ScatterAdd (tensor-index / embedding
  backward), Conv2d/Pool2d/BatchNorm backward nodes, RnnNode (SSA), Sort/TopK/
  MinMax; `concatenate`/`pad` autograd wrappers should emit Concatenate/PadNode
  instead of eager allocation + IndexedUpdate.
- Keep relu as `Cast(Gt(x,0))*ct` and gelu's `Erf(Mul(z,0.7071))` shapes (or
  update the matchers) so backward epilogue fusion keeps matching.

### 5.2 Recommended first slice ("Phase A: rules under the tape")
`fl/autograd/Vjp.{h,cpp}` with `vjp(const Node& fwd, primals, out, ct, want)`
dispatched by switch on NodeType; a generic `record(out, inputs)` helper in
Functions.cpp that captures the forward NodePtr and calls the rule at backward
time (falls back to the existing closure when the node type isn't covered).
Target identification and `backward()` unchanged. Migrate: Binary, Unary, Cast,
Reshape, Transpose, Sum/Mean, Matmul (all MatrixProperty combos), Tile (with the
backward fix), Where, Clip, Flip, Roll, Triangular, Cumsum. Keep gelu,
conv/pool/BN/RNN, index/embedding, softmax, CCE on closures. Prerequisites:
§1.1 optimizer/alias fix, withoutData fix, detach fix, Jacobian helper rewrite.
Tests: closure-vs-rule comparison per op (broadcast, scalar operand, f16),
JitBackwardEpilogueFusionTest stays green, backward of relu(linear) has no
CustomNode and no new external uses on forward nodes, `fl::ready(grad)` false
after `backward()`, bounded reachable-node count over N training steps.
Phase B (after StopGradient, build-before-eval invariant, RNG policy, new
nodes): JIT-graph walk with explicit param list; delete the tape.

### 5.3 Jacobian test helper (`test/autograd/AutogradTestUtils.h`)
Mechanism of the CUDA blow-ups: perturbing via `input.flat(i)` on a grad tensor
(+ `withoutData` allocation), three `detach().flat(i)=…` IndexedUpdates per
column, `fwdJacobian(span,i)=diff` = full-matrix IndexedUpdate per column
(O(nOut·nIn²) traffic, two full-matrix allocations per column); in backward,
`dout.detach().flat(j)=…` grows an IndexedUpdate chain that is never compacted
and re-optimized every row; other grad leaves (BN/conv weights) never zeroed →
lazy Add chains; cuDNN plans rebuilt per eval. Rewrite: never mutate `input`;
one-hot perturbation on non-grad copies; fresh one-hot `dout` per row; assemble
Jacobians on host; zero/avoid other grad leaves; small sizes on CUDA.

## 6. Architecture maps (for future engineers / agents)

### 6.1 JIT core flow
```
op → Tensor.cpp free fn → lhs.backend() (tensor's JitBackend*, not its device)
  → JitBackend::op → XNode::create(inputs, params, stream=nullptr default)
  → JitTensorBase{SharedData{DataStorage{ExternalUse(node)}, indexings, viewNode}}
Node: inputs_ (strong) | uses_ (raw back-refs) | externalUses_ | result_ |
  outputs_ (multi) | outputBuffer_.  Mutation = IndexedUpdateNode (SSA).
fl::eval → JitBackend::eval → JitTensorBase::eval: Optimizer::optimize(root)
  (in place; verifyGraph after each pass) → Evaluator::eval: buildPlan
  (iterative DFS, stops at evaluated nodes, useCount = uses + externalUses,
  sync edges only for explicit streams) → assignBuffers (allocates all) →
  executePlan (relativeSync, switch → dispatch_.op(ctx,out,...), decrement,
  unsetResult) → ensureResultInOutputBuffer → recordDataReadyEvent →
  JitBackend::eval → compact(): root → ValueNode(shallowCopy); projection root →
  parent RAUW'd to MultiValueNode.
BackendDispatch: ~50 fn ptrs, ctx = wrapped TensorBackend (makeDirectDispatch);
  no stream arg — CPU ops run on lhs's AsyncCPUStream, CUDA on the singleton.
Backward state: Deferred{Conv2d,Pool2d,Batchnorm}State hold the fwd NodePtr.
```

### 6.2 Optimizer pipeline (Optimizer.cpp; once per eval, no fixed point)
```
CPU : ConvBNFold → TransposeSimp → ScalarFold → AlgebraicSimp → CSE
      → [OneDnnPrimitivePostOpFusion] → ElementwiseFusion → ReductionOfElementwise
      → [OneDnnOpFusion]   (mostly preempted by ElementwiseFusion)
CUDA: ConvBNFold → TransposeSimp → ScalarFold → AlgebraicSimp → CSE
      → [CudnnSubgraphLowering] → [CublasLtBackwardEpilogueFusion]
      → ElementwiseFusion → ReductionOfElementwise → [CudaFusedKernelLowering]
Lines: AlgebraicSimplification 759, CudnnSubgraphLowering 1177, CublasLt bwd 919,
  OneDnnPrimitivePostOpFusion 600, NvrtcKernelCompiler 549, OneDnnOpFusion 410,
  CudaFusedKernelLowering 343, TransposeSimp 260, CSE 241, ScalarFolding 210,
  ElementwiseFusion 167, ConvBNFold 141, ReductionOfEW 123; infra: Pass 175,
  Optimizer 107, GraphVerifier 281, PatternMatcher 586, ActivationPatterns 220,
  FusionUtils 114 (dead). opt/ total ≈ 8.2k.
CPU FusedElementwise/FusedReduce nodes are evaluated op-by-op (no CPU codegen).
```
Pass invariants: (1) replacement keeps old node's shape AND dtype, and
`optimize()` preserves the root's; (2) never absorb a node with >1 consumer
counting ExternalUses; (3) `rewrite()` returns the node that received the old
node's uses; (4) no cycles — a replacement must not consume the node it
replaces; (5) multi-output: redirect all projections, never return a
multi-output node as root; (6) eval lambdas create only bare backend tensors
(`detail::makeTensor`, `toTensor<CudaTensor>`, `makeCPUTensor`), never
`Tensor()`/`Tensor(shape,dt)`/`fl::full`; (7) check library support at optimize
time — eval must not throw for an accepted rewrite; (8) treat evaluated nodes
as leaves.

### 6.3 Op dispatch and library map
```
a+b: operator+ → add → JitBackend::binary (virtual) → BinaryNode → Optimizer →
  Evaluator → profile wrapper → dispatch_.binary → CPUBackend::binary switch →
  OneDnnOps member → detail::onednn::applyBinop → AsyncCPUStream enqueue.
CPU:  binary arith/compare/min/max → OneDNN binary (ints in f32); exp/log/sqrt/
  tanh/rint/neg/sigmoid/abs/clip → OneDNN eltwise (needs contiguous); sin/cos/
  floor/ceil/log1p/erf/isnan → native (f32/f64, contiguous only); pow/mod/bitwise/
  logical → native host-sync; sum/mean/amin/amax/norm → OneDNN reduction;
  min/max/argmax/cumsum/sort/topk/flip/roll/tril/pad/nonzero → native;
  matmul → OneDNN (f64 via CBLAS); reshape/transpose/astype → OneDNN reorder
  (reshape copies); tile/concat → OneDNN concat; where → binary_select (f32/f16)
  else native; conv/pool/bn/rnn → OneDNN via synchronous executeNetwork (RNN bwd
  native BPTT).
CUDA: elementwise → Thrust (f32/f64 compute); astype/strided copy/transpose/tile/
  pad → custom kernels; reductions → CUB segmented + custom + Thrust; cumsum →
  CUB per row; sort/topk/median → CUB segmented sort on f32 keys; matmul →
  cuBLAS (cuBLASLt only in epilogue fusion); conv → cuDNN frontend (no cache);
  pool/bn/rnn → legacy cuDNN; random → cuRAND f32.
Streams: CPU = one process-wide AsyncCPUStream; CUDA = one backend stream
  (cuDNN uses a separate per-device stream joined by full syncs).
```
